# OCR档案应用工具 · 档序 ArchiveDesk 0.3

Windows 开源源码版。

本地扫描文件 OCR 与档案目录录入工具。基于 Windows 0.3 版源码整理，界面和识别、批量导出逻辑保持一致。

## 功能

- PDF/图片识别，保留 OCR 原文及字段证据，支持人工核对。
- 按每份文件的页眉提取密级，未识别或有冲突时留空提示。
- 正本数量默认 1，明确识别到的数量优先，可人工修改。
- 归档单位与责任者精确匹配联动，可关闭联动。
- 批量导入多个 PDF。重复文件和不支持的格式不会悄悄丢掉：导入后弹出摘要，逐个列出文件和跳过原因。批量识别时显示「第X个/共N个」，可以停止。已经识别完的结果保留，正在识别的那一份标为「已停止，可重新识别」，还没开始的仍是「待识别」。
- 识别状态与导出状态分开。必填项（含责任者）都有内容，且每个有数值的字段置信度不低于 0.85，状态为「已识别」；否则为「待核对」。用户手动标记后为「已核对」。读不了的文件为「失败」。导出成功或失败写在单独的导出状态里。导出前只按「待核对」的份数提示，可以选择继续或返回。
- 一键导出：每个 PDF 得到一个同名 Excel（`发文001.pdf` → `发文001.xlsx`），保存到用户选择的文件夹，并记住上次的文件夹。下次导出直接从该文件夹打开选择框，选定后立即写入本机项目文件。默认不覆盖，重名写成 `发文001(1).xlsx`；可勾选「覆盖同名文件」。不同文件夹里的同名 PDF 也会加序号。一份失败不影响其他文件。多页 PDF 仍是一份文件、一个 Excel。
- 导出结束时显示成功和失败份数、每个失败文件的中文原因，并可打开输出文件夹。输出文件夹里有 `处理清单.csv`（含源文件完整路径和导出时间；表头一致时追加，旧表头则另存 `处理清单_2.csv`），以及 `导出清单_时间.xlsx`（源文件完整路径、导出文件名及重命名原因、结果、中文原因、建议操作）。同一批里的同名文件加序号时，说明写「本批内同名」。再次点「导出 Excel」会跳过已经成功的文件；「只重试失败项」只处理失败项。
- 电子文件大小默认按 MB 写入，保留两位小数（不足 1 也保留小数，例如 0.28），设置里可以改成 KB 或 B。KB 同样保留两位小数，B 写入字节整数。
- 没有可读的标准模板，或模板里没有「管理类_件」时，程序仍能启动。窗口顶部浅红提示以「模板有问题，暂时无法导出 Excel」开头，写出真实原因，下一行写「模板路径：…」。导出按钮变灰。找不到模板或缺少工作表时，直接导出的报错也是这一行路径。不会改用其他工作表，也不会进入自定义核对模式。
- 识别进度写成「第 x/N 个 · 第 p/P 页」。本批已经量到页速之后，才显示「预计剩余约 N 秒」。
- 导入时如果有跳过的文件，汇总列出每一份和原因，可以复制。导出前只提示待核对的份数，按钮是「返回 / 继续」。导出结束给出可关闭的结果表（源文件路径、导出文件名、结果、中文原因、处理建议），并可以只重试失败项。
- 使用标准 XLSX 模板，按单元格写入数据，保留工作表、表头、列宽、字体、边框、合并单元格和其余 OOXML 部件。汇总目录导出是次要的可选项。

## Windows 启动

1. 安装 Python 3.11 64 位（包含 Python Launcher）。
2. 完整解压源码，在联网环境运行 `Setup.cmd` 安装依赖。
3. 运行 `Start.cmd`。
4. 在设置中选择你自己的原 Excel 模板及工作表，再导入扫描文件。

安装依赖后 OCR 可本地离线运行。可选 Ollama 只连接本机。项目数据保存在 `%LOCALAPPDATA%/ArchiveDesk/project.json`，为未加密 JSON。

开源包不含原业务模板、真实扫描件、提取结果、历史项目数据、第三方运行时和模型二进制。模板由用户自行提供，不会因开源而改变。

## 验证与限制

原 0.3 版本曾完成 Linux 环境单元测试、模拟扫描及模板格式验证。本次发布不表示已通过真实 Windows 设备验收；OCR 结果仍需核对，档案系统实际导入应另行测试。

测试不依赖未公开的业务模板或真实扫描件。示例模板由测试代码按「管理类_件 / 卷 / 卷内件」结构生成，下拉单位使用「示例单位A」这类占位名；扫描图由 Pillow 按本机中文字体绘制。Windows 上可运行全部测试：

```bat
set QT_QPA_PLATFORM=offscreen
.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"
```

Linux 需要中文字体（例如 `fonts-wqy-microhei`）以及 Qt offscreen 平台库。GitHub Actions 在 Python 3.11 上执行同一套测试。

`templates/standard_template.xlsx` 是本机私有模板，已写入 `.gitignore`，不要提交。程序在该文件存在且可读时用它导出；缺失或损坏时仍能启动，窗口顶部是红色中文提示，导出按钮不可用，设置里也不能改成自定义核对工作簿。打包前运行 `Build.cmd`，缺少该文件会直接停止。公开测试使用代码生成的假模板。主流程是批量导入 PDF、批量识别，然后点一次「导出 Excel」：每个 PDF 生成一个同名 xlsx，内容写在「管理类_件」。默认不覆盖已有文件，同名文件写成 `发文001(1).xlsx`。输出文件夹会记住。汇总导出是可选的次要功能。`python tools/compare_template.py <模板> <导出文件>` 检查工作表、列名和顺序、列宽、表头字体、表头边框、合并单元格，以及除数据单元格外的结构是否与模板一致。目录默认值在 `catalog_defaults.py`：保管期限为「30年」，载体类型为「纸质」，其余留空。这些值可在「字段与模型设置」中修改，保存在本机项目文件里，并按当前模板的下拉项校验。目标工作表默认是「管理类_件」。归档单位匹配不到时留空，记录回到待核对。
